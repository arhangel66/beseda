Privacy

Beseda records and transcribes conversations on your Mac. Recording and transcription are local; optional features can send text to services you choose. This page describes the app's data flows and limits.

What stays on your Mac

Beseda keeps call audio, transcription results and transcripts in ~/Library/Application Support/Beseda/calls/. In the parent Beseda/ folder, its calls.sqlite index contains call titles, transcript segments, summaries, matched calendar event information and attendee email addresses, and a webhook delivery log including endpoint response bodies. It also writes an app log. The SQLite index is not encrypted by Beseda. OpenRouter keys and webhook secrets are stored in the macOS Keychain.

Beseda sets owner-only file permissions in its data folder and uses macOS file protection where supported, which prevents access until the first login after a restart. These measures do not protect calls from someone using your unlocked account, software running as your user, or an administrator. Turn on FileVault to protect a lost Mac's disk.

When data leaves your Mac

  • OpenRouter summaries: If selected, Beseda sends the full transcript and call-type prompt to OpenRouter and the model it routes to. The built-in summary model does not send the transcript away.
  • Call-type classification: With an OpenRouter key and non-local classification, Beseda sends the opening of the transcript, call weekday and time, duration, and call-type names to OpenRouter's Decisions API (Jev).
  • Live key points: If enabled, accumulated live transcript lines go to the selected summary provider every few minutes. Live transcription itself is local.
  • LM Studio: If selected for summaries or live key points, text goes to the configured LM Studio server. That server may be on another machine; it is not necessarily local to your Mac.
  • Webhooks: If configured, Beseda sends the transcript, title, time and summary to your chosen endpoint. Endpoints must use HTTPS except for localhost. Beseda stores the endpoint's response body in its local index.
  • Downloads: Beseda downloads speech and summary model data from Hugging Face. The Store build ships a pinned signed llama.cpp helper with the app; it does not download that executable. The direct build may download the llama.cpp engine from GitHub and uses Sparkle for app updates. Apple handles Store app updates; Store update behavior has not been tested in a provisioned app. The app requests model files for downloads; this is not a guarantee about every field in a network request.

The “Local only” processing setting disables Jev and webhooks and uses the built-in model for summaries and live key points. Check your processing settings before recording sensitive calls.

Retention, deletion and backups

Audio retention can remove WAV files immediately after processing, after 30 or 90 days, or never. Failed and in-progress calls keep their audio for retry. Retention does not remove transcripts, summaries or exports. Deleting a call removes its managed folder, index entry and associated segments and webhook log, as well as its export copies when Beseda can access their folder. SQLite secure deletion removes deleted text from free pages. Copies already held by another service or a backup are not deleted by this action.

Beseda makes a calls.sqlite.v<version>.backup copy before migrating an existing database. Time Machine and other full-Mac backup tools may copy the data folder, including calls and migration backups. You can exclude the data folder from backups in Settings; this does not erase backups already made, and other backup tools may behave differently. Encrypt your backup disk if it holds sensitive calls.

If you enable Markdown export, files are written to the folder you choose outside Beseda's managed data folder. That folder's permissions and any iCloud Drive, Dropbox or other sync behavior apply. Audio retention does not remove exports. If access to an export folder has been revoked or it is no longer available, restore access before deleting the call so Beseda can remove its export copies; check other copies and backups yourself.

Recording responsibility

You are responsible for recording lawfully, getting any required consent from participants, and deciding where to store or send conversation data. Beseda does not notify participants for you. For sensitive calls, consider Local only and strict mode, FileVault, short audio retention, an unsynced export folder and encrypted or excluded backups.

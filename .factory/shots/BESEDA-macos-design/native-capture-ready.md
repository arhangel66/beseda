# Native concept capture fixture (BESEDA-322/325/328)

Source-only preparation, **not visual verification or a design candidate**. Build without launching an app: `swift build --package-path .factory/shots/BESEDA-macos-design/NativeConcepts --jobs 2`. The standalone SwiftPM library has no executable entry point, no Beseda controller, no audio, and no permissions. Do not use ImageRenderer or the never-ordered hosting view as native visual proof. A supervised, permitted native window capture is required before pixel critique; neither direction goes to Mikhail yet.

Exact ready-to-render selector: `NativeConcept(direction: .focus, scene: .idle)` (or `.ledger`, and `.recording` / `.archive`), from the `NativeConcepts` module. Render each of six combinations in both `.light` and `.dark` color schemes through a real hosted window only if separately authorized. Popover is 340 pt wide; archive is 1100 × 720 pt. `scene` is pure synthetic fixture state; no startup or controller binding occurs. BESEDA-321's [capture runbook](native-capture-runbook.md) is now present: this fixture covers its idle, recording-closed, and archive/result cells only. Expanded live, onboarding, processing and provider states are not covered. Its approval/watchdog STOP gate still blocks native capture. Recording: Pause → Stop → microphone/other-person levels → live disclosure, without archive commands. Idle: Start → Auto-record → recent → Conversations/Settings/Quit. Archive: 12 repeated-title calls in three day groups, search, selection, Results picker, lengthy summary and bottom transport. Focus leads with selected-call result and wider breathing room; Ledger prioritizes scan density and a wider sidebar. The UI uses actual SwiftUI controls and platform chrome, not bitmap stand-ins.

Earlier source-only verdict (BESEDA-325): **neither direction passed the hierarchy gate**. Focus changes headline scale, spacing, recent-card count and result width; Ledger changes those same weights and sidebar width. Both share the same control order, split view, segmented Results tab, summary body and transport, so they are density variants rather than truly different directions. Native `NavigationSplitView`, `List`, `Picker`, `Toggle`, `ProgressView`, toolbar and `.bar` transport avoid drawn chrome, but system titlebar, toolbar overflow and material appearance remain unverified. The recording Stop action is prominent and follows Pause as in the product; idle Start competes with the switch, while Ledger's three recent rows increase popover height. The 12 rows have repeated titles and time/app metadata; single-line truncation and day sections may not disambiguate them at narrow widths. The current result remains in the selected call's Results area; the previous-call link now explicitly opens a different call instead of implying the prior result belongs to the current summary. The synthetic “Ready to record” and “Auto-record is off” omit missing-model, denied-microphone, processing and paused warnings; do not treat them as readiness/privacy proof. No consent UI was invented. The reference sheet is mostly marketing art, not proof of native control behavior; no competitor parity is claimed. BESEDA-314's rejected offscreen-control/scroll rendering and BESEDA-318's failure handoff were not available as separate records in this checkout; the decision note records the former, so this verdict cannot claim direct review of both handoffs.

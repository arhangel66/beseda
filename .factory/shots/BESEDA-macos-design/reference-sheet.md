## macOS 14.2-compatible design constraints

Apple's public [macOS Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/) and topic pages [sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars), [toolbars](https://developer.apple.com/design/human-interface-guidelines/toolbars), [popovers](https://developer.apple.com/design/human-interface-guidelines/popovers), [color](https://developer.apple.com/design/human-interface-guidelines/color), [materials](https://developer.apple.com/design/human-interface-guidelines/materials), and [typography](https://developer.apple.com/design/human-interface-guidelines/typography) returned HTTP 200 on 2026-09-28. Their HTTP shell is JavaScript-rendered; this fetch does **not** verify the full rendered prose or newer OS-specific examples. For a 14.2 minimum, prefer existing AppKit/SwiftUI sidebar, toolbar, popover, system typography and semantic colors/materials instead of reproducing any site's marketing chrome or relying on macOS 26-only styling. Check actual light/dark, keyboard focus and text contrast in rendered Beseda views before adoption. This is a compatibility design inference, not an Apple endorsement.

Beseda-specific interpretation: the MacWhisper preview offers a useful transcript/inspector comparison to the existing archive detail, while Granola's capsule offers only a *visual* reminder to separate recording status from long-form results. The remaining references cannot verify Beseda's two-source capture indicators or first-run readiness. See [the evidence-limited sales audit](../../../docs/decisions/design-review-sales.md) for the app-side concerns; do not turn these images into competitor feature claims.

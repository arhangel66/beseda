# App Review recording policy preflight — preliminary, source-only

Checked against [Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) retrieved 2026-09-28 and the integrated Store source. This is not a legal consent opinion, a TCC/runtime test, or an App Review approval prediction. The owner must check current guidelines again before submission.

| Guideline | Source comparison and evidence level |
| --- | --- |
| [2.5.14](https://developer.apple.com/app-store/review/guidelines/#2.5.14): explicit user consent and clear visual and/or audible indication while recording/logging user activity | **Runtime/owner uncertainty, not a source-proven blocker:** Apple's exact wording requires apps to “request explicit user consent and provide a clear visual and/or audible indication when recording, logging, or otherwise making a record of user activity,” including microphone and screen recording. It does not specify a separate durable consent gate or modal. Manual Start is a deliberate recording action in the conversations toolbar (`Sources/Beseda/App/Views/ConversationsWindow.swift:110-131`), menu popover (`Sources/Beseda/App/Views/MenuBarPopover.swift:205-221`) and ⌘R command (`Sources/Beseda/App/BesedaApp.swift:107-119`); all reach `startCallRecording` (`Sources/Beseda/App/AppController.swift:443-466`). Auto-record is separately opt-in, off by default (`Sources/Beseda/App/AppSettings.swift:110-114,430`), through the Settings toggle with mic/system-audio explanation (`Sources/Beseda/App/Views/SettingsWindow.swift:215-222`), menu popover toggle (`Sources/Beseda/App/Views/MenuBarPopover.swift:221`) or command-menu toggle (`Sources/Beseda/App/BesedaApp.swift:118`). Onboarding describes audio capture (`Sources/Beseda/App/Views/OnboardingWindow.swift:17-25`), but closing it counts as completion, not consent (`Sources/Beseda/App/BesedaApp.swift:122-131`). Those recording-specific user actions plausibly constitute explicit consent; Apple does not clarify here whether a menu toggle alone is sufficiently informed. No demonstrated path starts capture merely from onboarding, TCC permission or calendar detection: detector start follows the persisted opt-in (`Sources/Beseda/App/AppController.swift:827-861`); calendar only predicts (`Sources/Beseda/App/AppController.swift:606`). Legacy `podushka.autoDetectEnabled` can migrate to true (`Sources/Beseda/App/AppSettings.swift:422-430,514-522`), preserving an earlier opt-in rather than creating a default-on state; an externally injected true defaults value could start detection without a fresh action, but that is not an app-authored bypass. Turning auto-record off stops future detection, not an already active recording (`Sources/Beseda/App/AppController.swift:827-838`); Stop remains separate. No new consent modal is supported by this evidence. **Source-proven indication implementation, runtime unverified:** status icon/timer (`Sources/Beseda/App/AppController.swift:177-190`, `Sources/Beseda/App/BesedaApp.swift:34-42`), stop control (`Sources/Beseda/App/Views/ConversationsWindow.swift:110-130`), auto-start notification (`Sources/Beseda/App/AppController.swift:970-976`, `Sources/Beseda/App/CallNotifications.swift:39-55`). Observe actual menu-bar visibility and notifications with real GUI/TCC; notification permission can be declined, so do not rely on the banner as sole indication. Whether participant notice/consent is legally adequate in each jurisdiction is owner/legal advice, not established by source. |
| [5.1.1(i–iv)](https://developer.apple.com/app-store/review/guidelines/#5.1.1): privacy policy, consent for data collection, withdrawal/deletion and accurate purpose/permissions | **Source-proven partial:** onboarding explains local audio/transcription and optional cloud text (`Sources/Beseda/App/Views/OnboardingWindow.swift:17-25`); archive has a deletion path (`Sources/Beseda/Storage/CallStore.swift:527-606`), and permission setup needs real GUI/TCC observation. Privacy policy presence, App Store metadata and the actual system permission strings need separate submission inspection; do not infer compliance from these source paths. The privacy nutrition declaration is outside this audit. |
| [5.1.2(i–ii)](https://developer.apple.com/app-store/review/guidelines/#5.1.2): disclose third-party use including AI and obtain explicit permission before sharing personal data; no repurposing without further consent | **Source-proven partial / owner review:** settings enumerate OpenRouter/Jev, remote LM Studio and webhook destinations (`Sources/Beseda/App/Views/SettingsWindow.swift:309-323`); webhook is gated by the setting and local-only mode (`Sources/Beseda/App/AppSettings.swift:263-276`) and its payload is described (`Sources/Beseda/App/Views/SettingsWindow.swift:810-821`). Confirm in real GUI that each provider choice and endpoint has an understandable explicit permission before any text is sent, and ask owner/legal to assess third-party permission for other participants. No blanket assertion that optional provider configuration alone fulfills Apple's requirement. |
| [2.5.2](https://developer.apple.com/app-store/review/guidelines/#2.5.2): self-contained bundle/container; no downloaded executable code changing features | **Source-proven design, runtime unverified:** model download is hashed and placed in models directory (`Sources/Beseda/Runtime/RuntimeInstaller.swift:186-204`); Store flavor's bundled helper and sandbox design are recorded in [sandbox decision](app-store-sandbox.md). Verify signed Store bundle, actual download content and sandbox paths in owner-supervised review; model data is not authorization to fetch executable updates. |

Auto-start is triggered by detected microphone-holder rather than an in-call confirmation (`Sources/Beseda/App/AppController.swift:793-797,854-861`); stop is available manually (`Sources/Beseda/App/AppController.swift:435-441`) and detector stop on release (`Sources/Beseda/App/AppController.swift:796-797`). Archive export and any sync destination must be evaluated by the owner against the privacy disclosure, not presumed local just because recording begins locally. No app, capture device, account, or network upload was exercised in this audit.

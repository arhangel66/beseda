# Native macOS visual directions

**Proposals, not app captures or a selected design.** The synthetic call, times, result and levels are illustrative. Mikhail rejected BESEDA-240 as “слабые схемы а не дизайн мак апп”; he did not choose a screen priority or direction. These are isolated SwiftUI bitmap renders, not a launched application. [Source constraints and unknowns](../../.factory/shots/BESEDA-macos-design/source-baseline.md) and [verified public reference sheet](../../.factory/shots/BESEDA-macos-design/reference-sheet.md) bound the exercise. The HIG topic pages returned JavaScript shells over HTTP: their prose was not verified. MacWhisper's promotional screenshot supplies a concrete transcript/inspector comparison, Granola's composite only a separation-of-status visual cue; CleanShot's inspected asset is an icon, not a UI benchmark. See [sales review](design-review-sales.md), [native-menu decision](native-menubar-app.md), and [English buyer gate](english-first-buyers.md).

## Two systems

**Focus** gives the current task a large rounded system-font heading, restrained indigo selection, a generous result reading column and compact two-source levels. Recording reduces the menu to Pause, Stop and a closed live disclosure. Results lead while a previous related call stays subordinate. Its large text consumes vertical space; longer localized strings need a real-window check. The large result line is proposed presentation of synthetic summary content, not a new extraction feature.

**Ledger** is denser and more documentary: smaller default system headings, wider sidebar, teal selection and a conventional Summary section instead of a pull quote. It prioritizes scanning archive rows and transcript/result navigation over an editorial reading moment. It has weaker immediate result emphasis, but scales better when result prose is long. Neither system adds a card grid, novel data model or competitor-derived chrome.

Both show existing Start/Auto-record/Recent/Conversations/Settings/Quit in idle; recording hides archive commands and has Pause then red Stop, two levels and collapsed live notes. Archive groups calls by day, selects Results for a processed call, retains Transcript/Info and a bottom player. Proposed title/metadata correspond to source fields. The sample result is made-up text of an existing result field. Search icon and top action band represent the archive's native searchable sidebar and toolbar; they are **not** screenshots of those controls. The offscreen renderer does not reproduce `MenuBarExtra` material, system toolbar, segmented picker, real switch/slider, focus ring, key-equivalent dispatch, hover, accessibility tree or window traffic lights. Do not implement this code in shipping paths until a direction is chosen.

## Assets

Each full PNG is a **SwiftUI proposal**, at 2× of 340×450 pt idle, 340×310 pt recording or 1100×720 pt archive. Its `390` companion is the same bitmap reduced to 390 px for legibility inspection, **not** a phone layout or a 390-pt app window. These sizes are proposed fixed render sizes; only width/default archive size are source-backed constraints. Source: [isolated renderer](../../.factory/shots/BESEDA-macos-design/render.swift).

Inspection found offscreen native Toggle and Slider rendered as warning glyphs and archive ScrollView omitted its content; replaced the isolated render-only controls with labeled state and a simple track, and used a bounded detail stack. This is a renderer limitation, not evidence of the product UI. Full archive shrinks illegibly to 390 px; inspect the full file at 1:1 for labels. Actual window chrome, keyboard focus order, VoiceOver, dynamic type, locale lengths, 14.2 system appearance, permission and recording flows remain unverified. No independent design critic reviewed these images; seek that review before presenting them as candidates. No direction is endorsed or production-ready.

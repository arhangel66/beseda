# Native macOS visual directions

**Proposals, not app captures or a selected design.** The synthetic call, times, result and levels are illustrative. Mikhail rejected BESEDA-240 as “слабые схемы а не дизайн мак апп”; he did not choose a screen priority or direction. These are isolated SwiftUI bitmap renders, not a launched application. [Source constraints and unknowns](../../.factory/shots/BESEDA-macos-design/source-baseline.md) and [verified public reference sheet](../../.factory/shots/BESEDA-macos-design/reference-sheet.md) bound the exercise. The HIG topic pages returned JavaScript shells over HTTP: their prose was not verified. MacWhisper's promotional screenshot supplies a concrete transcript/inspector comparison, Granola's composite only a separation-of-status visual cue; CleanShot's inspected asset is an icon, not a UI benchmark. See [sales review](design-review-sales.md), [native-menu decision](native-menubar-app.md), and [English buyer gate](english-first-buyers.md).

## Two systems

**Focus** gives the current task a large rounded system-font heading, restrained indigo selection, a generous result reading column and compact two-source levels. Recording shows Pause and Stop before the two meters and closed live disclosure. Results lead while a previous related call stays subordinate. Its large text consumes vertical space; longer localized strings need a real-window check. The large result line is proposed presentation of synthetic summary content, not a new extraction feature.

**Ledger** is denser and more documentary: smaller default system headings, wider sidebar, teal selection and a conventional Summary section instead of a pull quote. It prioritizes scanning archive rows and transcript/result navigation over an editorial reading moment. It has weaker immediate result emphasis, but scales better when result prose is long. Neither system adds a card grid, novel data model or competitor-derived chrome.

Both show existing Start/Auto-record/Recent/Conversations/Settings/Quit in idle; recording hides archive commands and has Pause then red Stop, two levels and collapsed live notes. Archive groups calls by day, selects Results for a processed call, retains Transcript/Info and a bottom player. Proposed title/metadata correspond to source fields. The sample result is made-up text of an existing result field. The isolated archive omits the system search field, toolbar, titlebar, player and segmented picker rather than counterfeit them; those remain present in the shipping app, not verified by these images. The offscreen renderer does not reproduce `MenuBarExtra` material, system toolbar, segmented picker, real switch/slider, focus ring, key-equivalent dispatch, hover, accessibility tree or window traffic lights. Do not implement this code in shipping paths until a direction is chosen.

## Assets

Each full PNG is a **SwiftUI proposal**, at 2× of 340×450 pt idle, 340×310 pt recording or 1100×720 pt archive. Popover `390` companions are source-pixel crops. Archive `390` companions are detail crops at source resolution, with separate sidebar crops linked below. They are **not** phone layouts or 390-pt app windows; the detail crop clips lines and cannot demonstrate full-text legibility at 390 px. These sizes are proposed fixed render sizes; only width/default archive size are source-backed constraints. Source: [isolated renderer](../../.factory/shots/BESEDA-macos-design/render.swift).

Inspection found offscreen native Toggle and Slider rendered as warning glyphs and archive ScrollView omitted its content; the isolated render uses labeled state and a bounded detail stack instead. It cannot demonstrate real switch or transport controls. Archive detail crops clip horizontal text; [Focus light sidebar](../../.factory/shots/BESEDA-macos-design/focus-archive-light-sidebar-390.png), [Focus dark sidebar](../../.factory/shots/BESEDA-macos-design/focus-archive-dark-sidebar-390.png), [Ledger light sidebar](../../.factory/shots/BESEDA-macos-design/ledger-archive-light-sidebar-390.png), [Ledger dark sidebar](../../.factory/shots/BESEDA-macos-design/ledger-archive-dark-sidebar-390.png) show the other important region. This is a renderer limitation, not evidence of the product UI. Full archive shrinks illegibly to 390 px; inspect the full file at 1:1 for labels. Actual window chrome, keyboard focus order, VoiceOver, dynamic type, locale lengths, 14.2 system appearance, permission and recording flows remain unverified. The independent BESEDA-314 critique rejected the predecessor images. The revised images have not passed independent review or complete full-size/390 inspection; clipped text and non-native controls make them unsuitable as native-fidelity evidence. No direction is endorsed or production-ready.

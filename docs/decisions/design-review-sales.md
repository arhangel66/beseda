# Sales UX screen audit

**Proposed, not a release verdict.** Reviewed 2026-09-27 from repository PNGs and source only. No app, browser UI, permissions, audio or user data were opened. Public competitor pages were fetched over HTTP for the limited comparison below. The PNG file modification dates are 2026-09-27 in this checkout, **not proof of capture date or current appearance**. BESEDA-75 images are older dark-mode preview states; BESEDA-112/99 and BESEDA-privacy show later light-mode seeded/preview states. They are not a consistent end-to-end session. Paths below are evidence, not publishable marketing assets. Current behavior is inferred from the named source, never silently attributed to a PNG.

## Category comparison: evidence, not a competitive teardown

[Development directions](development-directions.md) attributes an external analysis supplied by Mikhail, checked 2026-09-26: “no bot”, local transcription and summaries are not unique; it names Granola and MacWhisper among alternatives. [Landing brief](../product/landing-brief.md) proposes selling Beseda's three moments (during, after and before a related call) and explicitly forbids claiming rivals lack its features. [First-sale price](first-sale-price.md) records 2026-09-27 public-page observations: Granola's meeting notes/team service, MacWhisper's local transcription and optional cloud/BYOK AI, Superwhisper's dictation plus meetings/local and cloud models, Krisp's meeting recording/transcription plus noise cancellation. These are **secondary project notes**, not screenshots or an independently verified current UI comparison. Public HTTP pages checked for this review (2026-09-27):

These links are public promotional material, not observed sessions. No evidence here supports ranking their onboarding, detail hierarchy, privacy copy, recording controls, reliability or visual polish. Comparisons of subscriptions, licenses and conversion belong to pricing work, not this review. What Beseda can show in its own evidence is separate mic/system channels, local transcription, editable call-type prompts and the previous-related-call block; it cannot claim exclusivity or superior accuracy.

## Proposed priorities (impact hypothesis, not measured conversion)

| Priority / outcome | Issue and scope | Small ponytail step vs redesign |
| --- | --- | --- |
| **P0 trust / activation** | Prove that both sources were heard before first real call: onboarding test can complete with microphone only; the combined-meter old frame cannot prove remote sound. | Small: emphasize explicit two-channel outcome and one-sided consequence at Finish using existing monitor states. Redesign only if a tested first-call journey shows people miss it. |
| **P1 trust / purchase** | Processing settings make the relationship between downloaded speech model, summary provider, local-only override, classification and outbound text hard to scan. | Small: put existing effective-provider/privacy status beside the relevant action; do not add another toggle. Redesign: one task-led “what runs where” hierarchy across the long pane, with advanced models/prompts disclosed. |
| **P1 activation** | Skipping the model step can yield an idle menu with unavailable Start while auto-record remains on. | Small: use existing readiness state and a direct processing link to describe exactly what auto-record will do without a model. Do not promise text until downloaded. |
| **P1 purchase / repeat use** | Identical archive titles and prior-result/current-result proximity obscure the payoff of finding today's decision quickly. | Small: preserve collapsed previous-call digest and put a clear date/title on it. Redesign: differentiated archive rows and result hierarchy using real stored fields, without inventing AI-generated action cards. |
| **P2 trust** | Strict-mode deletion/backups and export are below the first Storage viewport; high-consequence choices deserve separate verification. | Small: keep the existing confirmation and risk words; test the full scroll, avoid a new settings framework. |
| **P2 polish** | Old recording and General screenshots show crowded/tall and empty states respectively, but both were changed in source. | No new code on old evidence. Obtain current, appearance-matched captures before reopening either finding. |
